# Инструкции проекта Leave Desk

## Назначение

- Разрабатывать адаптивное приложение для управления отпусками на Ruby on Rails.
- Считать `docs/product-brief.md` актуальным источником продуктовых требований.
- Считать нерешённые вопросы открытыми, а не неявными требованиями.

## Рабочий процесс

- Перед изменением поведения изучать связанные требования и код.
- Разделять требования пользователя, предположения и технические решения.
- Для нетривиальных изменений определять критерии приёмки и проверять их тестами.
- При изменении поведения или архитектуры обновлять спецификации и ADR.
- Сохранять историю отпусков; использовать явные переходы состояний вместо удаления.

## Правила предметной области

- Заявка относится к одному сотруднику и одному виду отпуска.
- Дата окончания не может предшествовать дате начала.
- Новая заявка получает статус `pending` («на рассмотрении»).
- Одобрить или отклонить можно только заявку в статусе `pending`.
- Отменить можно заявку в статусе `pending` или `approved`.
- При одобрении и отклонении сохраняются проверяющий и время решения.
- Сотрудник не может согласовать собственную заявку.
- Ожидающие и одобренные заявки одного сотрудника не могут пересекаться.
- Доступный остаток не ведётся и не ограничивает продолжительность заявки.

## Безопасность

- Не раскрывать учётные данные и персональные данные сотрудников в логах и примерах.
- Не добавлять production-зависимости без описания их назначения.
- Для бизнес-инвариантов предпочитать ограничения базы данных и транзакции.
- Не выполнять разрушительные операции с базой данных, Git, файлами или
  развёртыванием без явного разрешения.

## Разрешения на продолжение аудита

- Пользователь разрешил проверки production только на чтение: публичный HTTPS,
  статус GitHub Actions, состояние systemd и Docker, агрегирующие SQL-запросы и
  запуск ручных workflow аудита. Не выводить персональные данные и секреты.
- Разрешено читать подтверждённую резервную копию до пересоздания demo-данных,
  передавать её на одноразовый GitHub runner, проверять SHA-256 и восстанавливать
  только в изолированном PostgreSQL без сети. После проверки удалять временные
  файлы и контейнер. Production-БД и конфигурацию VPS не изменять.
- Для проверки R12-11 разрешено просматривать метаданные GitHub Actions и
  перечень сохранившихся резервных копий, искать более раннюю копию и проверять
  её целостность. Подтверждённую копию разрешено читать и восстанавливать только
  в изолированном PostgreSQL без сети на одноразовом runner. Выводить только
  агрегированные результаты без персональных данных и секретов; временные
  файлы и контейнер удалять. Production-БД и конфигурацию VPS не изменять.
- Пользователь разрешил commit и push проверенных изменений для закрытия
  тикетов. Перед каждым push сообщать хеш и состав коммита. Push в `main`
  автоматически запускает развёртывание; прямые изменения VPS требуют
  отдельного явного указания.
- Аудиторские отчёты, `docs/audit-continuation-prompt.md`,
  `docs/audit-universal-checks.md` и incident report сохранять вне коммитов.
  Универсальные проверки не коммитить отдельно.
