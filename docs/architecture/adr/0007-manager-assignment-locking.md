# ADR 0007: блокировка руководителя при назначении подчинённого

## Статус

Принято.

## Контекст

Проверка роли и активности руководителя при первом назначении подчинённого
могла выполняться одновременно с его понижением или деактивацией. Обе
транзакции видели допустимое состояние до изменения другой и сохраняли
недопустимую комбинацию.

## Решение

При обычном сохранении пользователя с новым руководителем блокировать строку
назначаемого руководителя до проверки и завершения записи. При изменении роли
или активности блокировать собственную строку перед проверкой подчинённых.
Несколько строк блокировать в порядке идентификаторов. Проверки читать из БД
без кэша запросов, а назначаемого руководителя проверять по заблокированной
версии строки. Это сериализует конкурирующие изменения через общий `FOR UPDATE`.

## Последствия

- Один из конкурирующих запросов ждёт завершения другого, затем проходит
  проверку по актуальному состоянию и при необходимости получает ошибку
  валидации.
- Прямые SQL-изменения, `update_all` и `update_columns` обходят проверки модели;
  административные изменения роли и подчинённости должны использовать обычное
  сохранение модели.
