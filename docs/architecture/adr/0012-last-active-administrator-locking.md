# ADR 0012: сохранение активного администратора

## Статус

Принято.

## Контекст

Администратор может изменить собственную роль и активность. Простая проверка
количества администраторов при сохранении допускает гонку: два последних
активных администратора могут одновременно увидеть друг друга и оба лишиться
доступа к управлению сотрудниками.

## Решение

При удалении роли или активности действующего администратора выполнять
сохранение в транзакции. До проверки блокировать `FOR UPDATE` строки всех
активных администраторов в порядке идентификаторов. После получения блокировок
считать актуальное число активных администраторов из БД и отклонять изменение,
если оно удалило бы последнего. Блокировки строк руководителей, необходимые для
назначения подчинённых, получать после блокировок администраторов.

## Последствия

- Конкурирующие изменения двух последних администраторов сериализуются: первое
  может пройти, второе увидит одного оставшегося администратора и не пройдёт.
- Создание другого активного администратора позволяет передать полномочия.
- Прямые SQL-изменения и `update_all` обходят проверки модели; для изменения
  ролей и активности использовать обычное сохранение `User`.
