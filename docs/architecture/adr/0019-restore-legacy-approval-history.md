# ADR 0019: восстановление одобрений отменённых исторических заявок

## Статус

Принято.

## Контекст

Первоначальная миграция истории создала событие решения только для заявок,
которые на тот момент ещё были одобрены или отклонены. У одобренной, а затем
отменённой заявки сохранились `reviewer_id`, `reviewed_at` и `review_comment`,
но её история содержала только создание и отмену из `pending`.

## Решение

Отдельная миграция находит отменённые заявки с сохранённым решением,
исторической отменой из `pending` и без события решения. Она добавляет
одобрение из сохранённых данных и меняет исходный статус отмены на `approved`.
Повторное применение не создаёт дубликаты. События добавляются SQL без
рассылки уведомлений о давно произошедших решениях. Перед записью миграция
проверяет хронологию и останавливается, если данные не позволяют сохранить
её. Обратная миграция запрещена, чтобы не удалять восстановленную историю.
После публичной HTTPS-проверки последний шаг автоматического выпуска выполняет
только агрегирующий SQL-запрос к production-базе. Он сравнивает число
отменённых заявок с сохранённым решением
с числом полных хронологических историй и не выводит идентификаторы,
комментарии или персональные данные. Совпадение времени одобрения и
`reviewed_at` показывается отдельно как признак возможного восстановления,
но не считается точным числом исправленных миграцией строк. Ручной workflow
выполняет тот же запрос при повторной проверке.
Поскольку demo-данные 20 октября были пересозданы, проверка текущей базы не
показывает прежние исторические строки. Ручной workflow отдельно проверяет
наличие и контрольную сумму сохранённой копии до пересоздания; содержимое
архива не выводится.
Для проверки исходной истории копия передаётся на одноразовый GitHub runner,
сверяется по SHA-256 и восстанавливается в PostgreSQL 16 контейнере без сети.
Выводятся только агрегаты; временный контейнер и копия удаляются при завершении
проверки. Production-БД и работающие контейнеры не изменяются.
При сбое восстановления полный вывод `pg_restore` остаётся во временном файле
runner и удаляется при завершении; журнал получает только безопасные категории,
код завершения и размер сообщения, чтобы диагностировать отказ без раскрытия
содержимого архива.
