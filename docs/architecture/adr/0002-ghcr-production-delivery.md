# ADR 0002: доставка production-образов через GHCR

## Статус

Принято.

## Контекст

Сборка образа на рабочей машине требует ручной передачи архива на VPS, а
сборка непосредственно на VPS расходует ресурсы production-сервера и зависит
от его текущего состояния. Выпуск должен использовать тот же коммит, который
успешно прошёл CI, и поддерживать однозначный откат.

## Решение

После успешного CI основной ветки GitHub Actions собирает Docker-образ,
публикует его в приватном GitHub Container Registry с неизменяемым тегом SHA
коммита и разворачивает этот тег на VPS по SSH. Адрес сервера, SSH-ключ и
запись `known_hosts` хранятся в GitHub Environment `production`, а не в Git.
Токен GitHub Actions передаётся Docker только на время скачивания образа и
после выпуска удаляется из конфигурации Docker на VPS.

## Последствия

- VPS больше не выполняет сборку приложения и не хранит исходный код.
- Каждый выпуск связан с конкретным проверенным коммитом; для отката достаточно
  вернуть тег предыдущего образа.
- Выпуск зависит от доступности GitHub Actions, GHCR и SSH-доступа к VPS.
- Изменения основной ветки автоматически попадают в production после успешного
  CI; доступ к environment и его секретам необходимо ограничивать.
