# ADR 0010: ежедневные локальные копии основной БД

## Статус

Принято как временная защита на действующем VPS. Внешняя копия и полное
восстановление приложения остаются открытыми.

## Контекст

На VPS был только Docker volume PostgreSQL. `bin/backup` запускался вручную и
не устанавливался на сервер при деплое. Пользователь выбрал частоту один раз
в сутки и попросил проверить время восстановления и свободное место. Отдельное
хранилище для копий пока не задано.

## Решение

`systemd` timer запускает `deploy/backup.sh` в 02:00 UTC ежедневно. Скрипт
создаёт логический архив только `leave_desk_production` с контрольной суммой,
хранит копии семь суток в `/var/backups/leave-desk` и перед созданием и после
него проверяет запас свободного места не меньше 2 ГиБ. Предыдущие копии
удаляются только после успешной новой. Каталог и архивы доступны root.

Ручной `bin/restore` перед вызовом `pg_restore` требует sidecar с одной записью,
имя в которой совпадает с выбранным архивом, и проверяет SHA-256 этого архива.
Это исключает проверку другого файла после переименования пары.
Ручной `bin/backup` резервирует уникальное временное имя через `mktemp`,
добавляет его суффикс к имени итогового архива и публикует архив и sidecar
без замены уже существующих файлов. Очистка после ошибки относится только к
файлам данного запуска.
Для ручного `bin/backup` новый каталог создаётся с режимом `0700`.
Существующий каталог должен принадлежать запускающему пользователю и уже
иметь режим `0700`; скрипт отклоняет остальные каталоги, не меняя их права.
Ручные скрипты выполняют предварительную проверку Bash и внешних команд до
операций с каталогом копий или базой данных. Поддерживаемое окружение —
GNU/Linux с Bash 4+, GNU coreutils и клиентскими утилитами PostgreSQL.

## Последствия

- При штатном выполнении частота даёт RPO около 24 часов плюс длительность
  задания; сбой может увеличить потерю данных. Ежедневный workflow GitHub
  проверяет свежесть, контрольную сумму, службу и место на диске. Получатель
  уведомления об ошибке workflow пока не подтверждён.
- Копия на том же VPS не защищает от утраты сервера или его диска. До настройки
  внешнего зашифрованного хранения C13 остаётся открытым.
- Копии `storage_data` и потенциальных будущих заданий Solid Queue требуют
  отдельного решения до включения этих функций.
- Замер пробного восстановления одной БД не подтверждает RTO всего приложения.
