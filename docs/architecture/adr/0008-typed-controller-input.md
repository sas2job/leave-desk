# ADR 0008: проверка типов на границе контроллеров

## Статус

Принято.

## Контекст

HTML-формы передают текстовые поля строками, но JSON-запросы могут передать
число или другой скаляр. До валидации модели такой ввод мог неявно стать
строкой или попасть в нормализацию, рассчитанную на строку. Структурированные
параметры года и месяца календаря молча заменялись текущими значениями.
Active Record также преобразует логическое `true` в идентификатор `1`, а
дробный идентификатор обрезает до целого числа. Проверка исходного значения в
модели уже не позволяла сохранить такие данные, но возвращала ошибку формы.
Разбор года без явного основания системы счисления принимал шестнадцатеричные
строки и считал строки с ведущим нулём восьмеричными.

## Решение

После `params.expect` проверять тип текстовых полей в контроллере. Если поле
передано, но не является строкой, возвращать HTTP 400 до изменения данных.
Для календарных фильтров применять ту же проверку до разбора года и месяца.
Год и месяц разбирать только из строк десятичных цифр; строки со знаком,
пробелами или разделителями недопустимы. Для некорректной строки сохранять
действующий возврат к текущему году или месяцу.
Идентификаторы связанных записей принимать только как положительные целые
числа или строки с десятичными цифрами; пустое значение оставлять модели для
проверки обязательности или очистки необязательной связи. Некорректный тип
или дробное значение возвращает HTTP 400 до изменения данных.
Некорректные скалярные значения месяца по-прежнему возвращают текущий месяц,
а ошибки содержания текстовых полей проверяются моделью и дают HTTP 422.

## Последствия

- JSON-запросы с числом вместо текста не создают и не изменяют записи.
- Логические и дробные значения идентификаторов вида отпуска и руководителя
  отклоняются контроллером с HTTP 400; проверка в модели остаётся защитой для
  других путей записи.
- Структурированные календарные фильтры не маскируются значениями по умолчанию.
- Приложение не объявляет публичный JSON API; проверка защищает существующие
  контроллеры от неоднозначного ввода.
