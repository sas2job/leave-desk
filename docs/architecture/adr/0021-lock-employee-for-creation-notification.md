# ADR 0021: блокировка сотрудника при создании заявки

## Статус

Принято.

## Контекст

Заявка строится через association пользователя, загруженного при
аутентификации. Пока сохранение ждёт блокировку вида отсутствия или календаря,
администратор может сменить руководителя. Объект сотрудника в association
остаётся устаревшим, поэтому событие создания могло уведомить прежнего
руководителя.

## Решение

При создании заявки после вида отсутствия и календарей блокировать строку
сотрудника `FOR UPDATE`, перечитывать её без query cache и заменять объект в
association. Заявку, событие и уведомление сохранять в той же транзакции, пока
блокировка сотрудника удерживается. Порядок блокировок при создании: вид
отсутствия, годы и строки календарей по возрастанию, сотрудник, новая заявка.

## Последствия

- Если перевод сотрудника завершился первым, создание перечитывает нового
  руководителя и уведомляет только его.
- Если создание заблокировало сотрудника первым, перевод ждёт commit, а
  уведомление относится к руководителю на момент фиксации заявки.
- Если руководитель ещё не назначен, событие создания сохраняется без
  уведомления; последующее назначение не создаёт уведомление задним числом.
- Прямые SQL-изменения `manager_id` в обход модели не участвуют в протоколе
  блокировок и остаются вне поддерживаемого пути изменения данных.
