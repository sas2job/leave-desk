# ADR 0017: ограничения неудачных попыток входа

## Статус

Принято.

## Контекст

Прежний лимит Rails считал все запросы входа с одного IP до проверки пароля.
Одиннадцать сотрудников за общим NAT могли исчерпать лимит успешными входами.
Один IP также не отражает попытки подобрать пароль одной записи с разных сетей.

## Решение

Считать только неудачные попытки: 10 на нормализованный адрес почты и 100 на
IP за три минуты. Проверять оба лимита до аутентификации. При отказе по любому
лимиту возвращать одинаковое сообщение без раскрытия существования записи.
Пароль с NUL-символом отклонять до вызова BCrypt и учитывать как обычную
неудачную попытку. При административной записи тот же ввод отклонять на уровне
модели с ошибкой поля до вычисления хеша пароля.
Ключи кеша содержат HMAC от адреса или IP, вычисленный с секретом приложения,
а не исходные значения. Использовать существующий Rails cache store; новые
production-зависимости не требуются. В production системный таймер каждые
15 минут вызывает `Rails.cache.cleanup` внутри действующего web-контейнера,
чтобы `FileStore` физически удалял истёкшие записи, а не только считал их
недействительными при следующем чтении.

## Последствия

- Успешные входы сотрудников за одним NAT не исчерпывают лимит.
- Счётчики в текущем файловом кеше одного контейнера теряются при его замене.
  При запуске нескольких web-контейнеров потребуется общее хранилище счётчиков.
- Уже заблокированная запись снова допускает вход после истечения срока кеша.
- Очистка файлового кеша сохраняет неистёкшие счётчики. Unit-файлы требуется
  установить или обновить на сервере после выпуска.
