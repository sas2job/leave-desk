# ADR 0009: блокировка вида отпуска при первой заявке

## Статус

Принято.

## Контекст

Первая заявка и изменение способа учёта праздников могли параллельно пройти
проверки по прежнему состоянию и сохранить несовместимый результат. В частности,
заявка могла использовать старую политику, а изменение — не увидеть заявку.

## Решение

При сохранении новой заявки или смене её вида блокировать строку выбранного
вида отпуска до проверки и завершения записи. Перед проверкой заменить
возможный устаревший объект ассоциации заблокированной версией из базы. При
изменении способа учёта праздников блокировать строку самого вида до проверки
существующих заявок и записи; проверку выполнять без кэша запросов. Для обоих
путей использовать транзакцию и `FOR UPDATE`.

## Последствия

- Если первая заявка сохранилась раньше, смена политики ждёт и отклоняется.
- Если смена политики завершилась раньше, заявка проверяется по новому правилу.
- Прямые SQL-изменения и методы, обходящие обычное сохранение модели, не
  получают этой защиты.
- Изменение календаря и сохранение исторической длительности определены в
  ADR 0013.
