# ADR 0027: постраничный просмотр истории

## Статус

Принято.

## Контекст

Списки личных и подчинённых заявок и уведомлений загружали всю сохранённую
историю. Удаление истории противоречит требованиям аудита. Смещение (`OFFSET`)
делает просмотр нестабильным при появлении новых записей.

## Решение

Показывать не более 25 записей за запрос в порядке убывания ID. Ссылка на
старую страницу передаёт исключительный курсор `before=<id>`; наличие следующей
страницы определяется выборкой 26 записей. Курсор ограничен положительным
64-битным целым. Добавить индексы `(employee_id, id)` и `(recipient_id, id)`
для личных заявок и уведомлений. Область доступа применяется до пагинации.

Ссылки из уведомлений задают курсор непосредственно перед связанной заявкой,
чтобы она присутствовала даже после накопления новых записей. Проверка наличия
непрочитанных уведомлений остаётся глобальной, как и операция «отметить все».

## Последствия

Размер ответа и число загружаемых записей ограничены. Новые записи не
сдвигают уже открытые старые страницы. Навигация «к новым» возвращает на
первую страницу; общего снимка истории между запросами нет.
