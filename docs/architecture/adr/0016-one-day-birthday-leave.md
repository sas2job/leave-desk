# ADR 0016: однодневный выходной в день рождения

## Статус

Принято.

## Контекст

`BIRTHDAY` существует как отдельный вид отсутствия, но общий ввод периода
позволял создать заявку этого вида на несколько дней. Пользователь установил
для него продолжительность в один день.

## Решение

При создании заявки с кодом вида `BIRTHDAY` разрешён только один полный
календарный день: одинаковые даты начала и окончания, начало утром и окончание
в конце дня. Проверка выполняется в модели до сохранения заявки и события.

Код `BIRTHDAY` служит стабильным идентификатором этой политики. После создания
системного вида изменить код нельзя ни через административную форму, ни через
обычное сохранение модели. Название, активность и остальные разрешённые
настройки вида остаются редактируемыми. Seed по-прежнему находит системный вид
по стабильному коду и не создаёт параллельную запись после административного
редактирования.

## Последствия

- Новый многодневный или половинный период для `BIRTHDAY` отклоняется с ошибкой
  формы.
- Существующие заявки и их история не переписываются этой проверкой; правила
  переходов состояний для исторических заявок сохраняются.
- Администратор видит системный код `BIRTHDAY` как неизменяемое поле; попытка
  подменить его в запросе отклоняется валидацией модели.
- Вопросы допустимой даты, частоты и праздников требуют отдельного решения.
