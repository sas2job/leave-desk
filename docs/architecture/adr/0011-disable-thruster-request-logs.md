# ADR 0011: отключить журнал запросов Thruster в production

## Статус

Принято для Compose-конфигурации; проверка после деплоя ожидается.

## Контекст

Rails фильтрует имена, даты рождения, адреса и комментарии в своих строках
`Started` и `Parameters`. Проверка на действующем сервере 14 октября 2026 года
показала, что Thruster независимо пишет JSON-строку `Request` с исходным
параметром `query`. Синтетические значения полей попадали в неё без фильтрации.
Тот же путь мог раскрыть персональные данные, переданные в URL.

## Решение

Задать сервису `web` переменную `LOG_REQUESTS=false`, поддерживаемую Thruster.
Журнал запросов Thruster отключается целиком. Rails продолжает писать запросы
в stdout с действующим `filter_parameters`. Для `web` ограничить Docker
`json-file` тремя файлами по 10 МиБ, чтобы этот журнал не рос без ограничения.

## Последствия

- Метрики отдельной строки Thruster `Request` больше не доступны в Docker-логе;
  для разбора запросов остаются строки Rails с идентификатором запроса.
- После деплоя нужно повторить запрос с синтетическими значениями в URL и
  убедиться, что они не появляются ни в одной строке лога.
- Если появится новый reverse proxy или журнал доступа, его строки URL нужно
  проверить отдельно: фильтр Rails на них не распространяется.
- Уже записанные строки нельзя считать очищенными только из-за изменения
  конфигурации. Доступ к старым логам остаётся ограниченным.
