# ADR 0026: ограничение журналов долгоживущих контейнеров

## Статус

Принято; применено на VPS выпуском `796d360` 23 октября 2026 года.

## Контекст

У `web` уже задана ротация Docker-логов. `caddy` и `db` использовали
настройки daemon по умолчанию, при которых `json-file` может расти без
ограничения и занять дисковое пространство сервера.

## Решение

Явно задать для `caddy`, `db` и `web` драйвер `json-file` с тремя файлами
по 10 МиБ. После выпуска пересоздать уже запущенные `caddy` и `db` и сверить
их действующие настройки логирования; локальный Compose-файл сам по себе не
подтверждает политику работающих контейнеров.
Согласовывать `db` через Compose после остановки `web` и до миграций:
Compose пересоздаёт контейнер при изменении конфигурации, сохраняя том данных.
После запуска сервисов проверять эффективный `LogConfig` всех трёх контейнеров
в workflow выпуска.

## Последствия

- Журналы этих сервисов получают верхнюю границу около 30 МиБ на сервис.
- Старые журналы и другие источники расхода диска требуют отдельного контроля.
