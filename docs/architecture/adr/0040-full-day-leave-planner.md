# ADR 0040: полный календарный день в планировщике заявки

## Статус

Принято.

## Контекст

Форма называла интервал 09:00–18:00 «весь рабочий день». Расчёт длительности
заявки при этом использует доли календарных суток: для одного дня такой
интервал даёт 0,375 дня. Это мешало планировать ежегодный отпуск на заданное
число календарных дней. Отдельный список «Быстрый выбор» содержал только этот
вариант и не объяснял, как работают крайние и промежуточные дни периода.

## Решение

Чекбокс «Весь день» задаёт для новой заявки интервал 00:00–24:00 на всех
выбранных датах. Сервер применяет эти границы по значению чекбокса, даже если
клиент отправил другие значения скрытых полей времени. При снятой отметке
пользователь выбирает время начала первого и окончания последнего дня в
пределах 09:00–18:00. Действующий расчёт дробных дней сохраняется и для
ежегодного отпуска.

Планировщик рядом с полями показывает границы периода и отмечает полные и
неполные дни. Для полного периода он показывает число учитываемых дней с
учётом правил выбранного вида и федеральных праздников текущего года. Список
длинного периода сокращается до первых и последних семи дат. Серверная
валидация и сохранение заявки остаются источником окончательного результата.

## Последствия

Полный ежегодный отпуск на 28 календарных дней можно указать без дробной
длительности. Прямые запросы без чекбокса сохраняют прежний формат точного
времени. Форма работает без JavaScript: чекбокс обрабатывается сервером, а
поля дат и времени остаются доступны для ручного ввода.
