# ADR 0035: точные границы периода отсутствия

## Контекст

Выбор «с утра» и «после полудня» не фиксировал часы отсутствия на части
рабочего дня. Пользователь уточнил, что точные часы нужны для всех видов
отсутствия. Исторические заявки уже содержат только границы половин дня,
поэтому приписывать им точные часы задним числом нельзя.

## Решение

- Новая форма принимает начало и окончание с точностью до минуты. Для полного
  календарного дня используются `00:00` и `24:00`; последнее значение разрешено
  только как конец указанной даты. В форме время выбирается из списков с шагом
  15 минут; серверная модель хранит границы в календарных минутах.
- Новые заявки сохраняют минуты от начала каждой граничной даты и расчётную
  длительность в календарных минутах. Старые заявки сохраняют прежние части дня
  и длительность в половинах дня. Интерфейс различает эти два формата.
- Ограничение PostgreSQL проверяет пересечения активных заявок по единому
  временному диапазону: точные минуты для новых заявок, прежние границы для
  старых. Соседние интервалы допустимы.
- Праздники, исключаемые видом отсутствия, вычитаются как полные календарные
  даты. Частичные граничные даты учитываются по точным минутам. Сохранённая
  длительность изменяется только при явной проверке календаря администратором.
- Календарь по-прежнему показывает ячейки дня двумя половинами для компактности;
  описание ячейки содержит точные границы новой заявки. Несколько соседних
  заявок внутри одной половины дня показываются отдельными метками.

## Последствия

Существующие записи не мигрируют в вымышленные часы. Продолжительность в
минутах отражает календарный интервал с правилами праздников; приложение не
рассчитывает заработную плату и не знает индивидуальный рабочий график.
Откат схемы после появления новых заявок невозможен без потери точности.
