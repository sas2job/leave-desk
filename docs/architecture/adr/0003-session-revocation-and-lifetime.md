# ADR 0003: отзыв и срок действия сессий

## Статус

Принято.

## Контекст

Сессии сохранялись после деактивации пользователя и замены пароля. Подписанная
cookie была постоянной, а серверная запись сессии не имела срока действия.
Это позволяло продолжать доступ с ранее открытого браузера. Между проверкой
пароля и созданием сессии возможна смена учётных данных.

## Решение

При изменении `active` или `password_digest` удалять серверные сессии
пользователя в той же транзакции, что и обновление пользователя. После
проверки пароля создавать новую сессию только под блокировкой записи
пользователя, повторно проверив активность и значение проверенного хеша
пароля. При возобновлении сессии дополнительно проверять активность
пользователя и возраст серверной записи. Абсолютный срок действия сессии и
cookie — 30 дней от входа; для ранее выданных постоянных cookie действует тот
же серверный предел.

Истёкшие записи удаляются ежедневным таймером systemd. Очистка выбирает записи
по `created_at` и удаляет их партиями по 1000, чтобы один запрос к БД не
охватывал весь накопленный объём. Граница совпадает с проверкой возраста при
аутентификации: запись истекает только при `created_at < now - 30.days`.

## Последствия

- После деактивации или смены пароля пользователь должен войти заново.
- Изменение других полей пользователя не завершает его сессии.
- Уже выполняющийся запрос может завершиться, но последующие запросы со
  старой сессией отклоняются.
- История заявок, решений и событий не затрагивается.
