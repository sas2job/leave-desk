# ADR 0058: архив перед пересозданием demo-набора

Статус: принято. Дата: 12.11.2026.

## Контекст

Пользователь явно разрешил пересоздать demo-данные staging под новые остатки,
сохранив прежние пароли. Простое удаление нарушает сохранность истории,
а отмена использованных отпусков не возвращает уже потраченные дни и оставляет
смешанный набор старых и новых демонстрационных сценариев.

## Решение

Отдельная операция сохраняет связанные записи demo-активности в неизменяемый
`DemoSeedArchive`, затем заменяет только рабочие demo-записи в той же транзакции.
Пользователи и сессии не пересоздаются. Новый набор создаётся штатными моделями
с резервированием, согласованием и закрытием, после чего проверяется баланс.

План привязан к снимку исходного состояния, включая изменения учётных записей,
но выводит только SHA-256 плана и агрегаты. Перед применением обязательны свежая
копия и проверка полного восстановления на изолированном runner без сети.
Согласование операции и эксплуатационная сериализация используют существующий
ручной workflow и группу `production`; автоматический деплой не пересоздаёт данные.

## Последствия

Старая история остаётся в архиве и резервной копии, а текущий интерфейс показывает
новый demo-набор. Архив не содержит пользователей или их парольных хешей.
Нельзя использовать этот сценарий для реальных сотрудников; область ограничена
активными demo-аккаунтами. Объём архивов увеличивается при каждом явном пересоздании;
автоматическая очистка или срок удаления не вводятся.
