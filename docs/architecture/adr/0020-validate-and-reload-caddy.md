# ADR 0020: проверка и применение конфигурации Caddy при выпуске

## Статус

Принято.

## Контекст

Копирование `Caddyfile` на VPS не обновляет уже запущенный процесс Caddy.
Проверка приложения на loopback также не подтверждает публичный HTTPS.
Некорректный файл нельзя оставлять вместо действующей конфигурации.

## Решение

Загружать новый файл отдельно как `Caddyfile.next` и проверять его командой
`caddy validate` в одноразовом сервисе Compose. После успешной проверки
копировать его содержимое в файл bind mount, согласовывать изменения образа и
окружения Caddy через Compose и вызывать `caddy reload`. При ошибке применения
восстанавливать предыдущий файл и пытаться вернуть его в работающий сервис.
После выпуска проверять публичный HTTPS с проверкой сертификата. Кандидат с
ошибкой синтаксиса не меняет действующую конфигурацию.
