# Непрерывная интеграция

GitHub Actions запускает проектные проверки для каждого pull request и каждого
изменения основной ветки. Workflow использует версию Ruby из `.ruby-version` и
PostgreSQL 16.

Единственная точка входа для локального и удалённого запуска:

```sh
bin/ci
```

Команда подготавливает тестовую базу и последовательно проверяет стиль Ruby,
уязвимости Ruby-зависимостей, безопасность приложения и тесты. Seeds
проверяются транзакционным тестом `test/scripts/seeds_test.rb`, поэтому проверка
не оставляет данные в тестовой базе. Сбой любого шага завершает workflow с
ошибкой.

Проект пока не содержит каталога `test/system`, поэтому отдельный запуск
`test:system` в CI отсутствует. При появлении системных тестов job следует
вернуть вместе с браузерными зависимостями и сохранением диагностических
скриншотов.

После успешного CI основной ветки запускается workflow `Deploy`. Он собирает
Docker-образ именно проверенного SHA, публикует теги SHA и `latest` в GHCR и
разворачивает SHA-тег в environment `production`. Ручной запуск `Deploy`
доступен через `workflow_dispatch`.
