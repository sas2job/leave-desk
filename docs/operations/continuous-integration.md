# Непрерывная интеграция

GitHub Actions запускает проектные проверки для каждого pull request и каждого
изменения основной ветки. Workflow использует версию Ruby из `.ruby-version` и
PostgreSQL 16.

Для локального запуска всех проверок используйте:

```sh
bin/ci
```

Команда подготавливает базу, проверяет стиль Ruby, уязвимости зависимостей и
безопасность приложения. Затем она запускает весь набор тестов на пустой тестовой
базе, загружает справочные данные и отдельно проверяет их повторную загрузку и
сохранность правок администратора. После этого запускаются браузерные тесты.
Проверки справочников и браузерные тесты используют один процесс, чтобы работать
именно с предварительно засеянной базой. Остальные тесты создают собственные
записи и предполагают отсутствие справочников до начала сценария.
Сбой любого шага завершает проверку с ошибкой.

GitHub Actions выполняет проверки в отдельных jobs и повторяет тот же сценарий.
После загрузки справочников запускаются `test/scripts/seeds_test.rb`,
`test/models/federal_calendar_seed_test.rb` и
`test/models/regional_calendar_seed_test.rb`. Они транзакционны и не меняют
итоговое состояние базы.

После успешного CI основной ветки запускается workflow `Deploy`. Он собирает
Docker-образ именно проверенного SHA, публикует уникальный тег запуска и тег
`latest` в GHCR, а в environment `production` разворачивает возвращённый
BuildKit manifest digest. Ручной запуск `Deploy` доступен через
`workflow_dispatch`.

Перед production job отдельный job проверяет, что CI был вызван `push` ветки
`main` исходного репозитория, а SHA этого запуска по-прежнему совпадает с
текущей вершиной `main`. Успешный CI для pull request, включая fork с веткой
`main`, и устаревший CI не запускают автоматический выпуск. Ручной запуск
использует SHA выбранного ref и не проходит проверку текущей вершины `main`.
Для отката к прежнему образу используется digest, сохранённый в каталоге
релиза, и отдельная процедура развёртывания.
