# Проверка Docker build context

Перед сборкой production-образа Docker применяет корневой `.dockerignore`.
Вложенные `.env` и резервные копии не должны попадать в контекст, в том числе
если они не отслеживаются Git. Разрешённый шаблон `.env.example` остаётся
доступным для сборки.

## Проверка C8 (13.10.2026)

На локальном Docker 29.1.3 выполнены диагностические сборки из корня проекта
с временным Dockerfile `FROM scratch`, `ARG PROBE` и `COPY ${PROBE} /probe`.
Проверялись только несекретные временные файлы; результат не публиковался и
не экспортировался в образ. Положительные сборки завершились успешно, а
попытки `COPY` исключённых файлов завершились ошибкой отсутствия источника.

| Проверенный путь | Результат |
| --- | --- |
| `c8_context_probe/visible.txt` | Доступен |
| `c8_context_probe/nested/.env.example` | Доступен |
| `c8_context_probe/.env` | Исключён |
| `c8_context_probe/nested/.env.local` | Исключён |
| `c8_context_probe/backups/backup.txt` | Исключён |
| `c8_context_probe/nested/archive.dump` | Исключён |
| `c8_context_probe/nested/archive.dump.sha256` | Исключён |
| `c8_context_probe/nested/archive.sql.gz` | Исключён |

Временные файлы после проверки удалены. При изменении `.dockerignore` повторить
проверку на реальном корне проекта: создать несекретные файлы-кандидаты,
проверить доступность через `COPY`, затем удалить файлы-кандидаты. Проверка
не заменяет просмотр состава контекста перед публикацией образа.
