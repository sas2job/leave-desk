# Пересоздание demo-данных staging

Операция предназначена для тестового VPS Leave Desk. Она требует явного
разрешения пользователя на пересоздание и сохранение действующих учётных записей.

1. Развернуть проверенный код с миграциями остатков и `demo_seed_archives`.
2. Запустить workflow **Correct demo calendar 2026** с `operation=reseed_demo`,
   `mode=plan`, пустым `plan_digest`. План сохранять как агрегированный результат.
3. Проверить область и объём. План не меняет данные; пароли и сессии не выводятся.
4. Запустить тот же workflow с `mode=apply` и SHA-256 полученного плана.
   Workflow сначала создаёт свежий снимок в `/var/backups/leave-desk`, затем
   передаёт копию на runner, проверяет SHA-256 и полное восстановление в
   PostgreSQL 16 с `--network none`. Ошибка блокирует применение.
5. Применение сохраняет старую историю demo-активности в `demo_seed_archives`,
   пересоздаёт рабочие записи и проверяет сохранность всех учётных записей,
   паролей, сессий, календарей и видов отсутствия. Учётные данные в архив
   приложения не копируются. Восстановленная проверочная БД не имеет сети,
   временные файлы и контейнер удаляются по завершении.
6. Итог должен содержать `passwords_unchanged=true`, `sessions_unchanged=true`,
   `calendars_unchanged=true`, `archive_created=true`, положительные остатки
   меньше 50 дней и согласованные счётчики. Затем проходят аудит истории и `/up`.

При устаревшем плане нужно получить новый `plan`, а не обходить проверку.
Резервная копия VPS и архив истории в БД сохраняются после операции.
Обычный `db:seed` не пересоздаёт staging и не меняет пароли существующих аккаунтов.
