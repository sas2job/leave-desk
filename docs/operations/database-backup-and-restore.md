# Резервное копирование и восстановление PostgreSQL

## Резервная копия

```sh
DATABASE_URL='postgresql://…' BACKUP_DIRECTORY=/secure/backups bin/backup
```

Команда создаёт архив `pg_dump` в custom-формате и файл SHA-256. Каталог и
файлы доступны только владельцу процесса. `DATABASE_URL` не выводится.

Архивы содержат персональные данные. Их необходимо хранить в зашифрованном
хранилище с отдельным управлением доступом и политикой срока хранения. Скрипт
не удаляет старые копии автоматически.

## Восстановление

Восстановление выполняется только в заранее созданную пустую базу. Скрипт не
очищает существующую базу и требует явного подтверждения:

```sh
RESTORE_DATABASE_URL='postgresql://…' \
ALLOW_DATABASE_RESTORE=yes \
bin/restore /secure/backups/leave-desk-YYYYMMDDTHHMMSSZ.dump
```

Перед началом проверяется контрольная сумма. `pg_restore` работает одной
транзакцией и прекращает выполнение при первой ошибке.

## Проверка восстановления

После восстановления в изолированную базу:

1. запустить `bin/rails db:migrate:status` с URL восстановленной базы;
2. проверить количество ключевых записей без вывода персональных данных;
3. выполнить вход тестовой учётной записью и основные пользовательские сценарии;
4. зафиксировать дату проверки, архив и результат;
5. удалить тестовую базу по утверждённой процедуре.

Резервная копия считается проверенной только после успешной репетиции
восстановления. Периодичность, срок хранения и целевые RPO/RTO определяются
перед production-развёртыванием.
