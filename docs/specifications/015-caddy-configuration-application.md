# Спецификация 015: применение конфигурации Caddy

## Критерии приёмки

1. Кандидат проверяется через `caddy validate` до изменения действующего файла.
   После проверки файл публикуется атомарно и сервис согласуется через Compose.
2. Перед `caddy reload` скрипт ждёт ответа admin endpoint на
   `127.0.0.1:2019/config/` не более 20 секунд по умолчанию. Срок можно задать
   `LEAVE_DESK_CADDY_READY_TIMEOUT_SECONDS` в пределах 1–60 секунд.
3. Временная неготовность допускает повторную проверку. Истечение срока и
   ошибка reload после готовности дают разные сообщения и ненулевой статус.
4. При ошибке применения предыдущий файл восстанавливается атомарно, Caddy
   пересоздаётся из него, а готовность и reload проверяются с тем же пределом.
   Невозможность подтвердить восстановление сообщается оператору.
