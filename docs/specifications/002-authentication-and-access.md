# Спецификация 002: аутентификация и доступ

## Критерии приёмки

1. Неавторизованный пользователь при обращении к защищённой странице
   перенаправляется на форму входа.
2. Активный пользователь может войти по нормализованному адресу электронной
   почты и паролю.
3. Неверные учётные данные и учётная запись со статусом `active: false` не
   создают сессию и возвращают одинаковое сообщение об ошибке.
   Форма сохраняет введённый адрес электронной почты; отсутствующие и
   структурированные вместо строк значения полей отклоняются без ошибки сервера.
4. После успешного входа пользователь возвращается на первоначально запрошенную
   страницу либо на главную страницу.
5. Выход удаляет серверную сессию и cookie браузера.
6. Идентификатор сессии хранится в подписанной cookie с атрибутами `HttpOnly` и
   `SameSite=Lax`.
7. Частота неудачных попыток входа ограничивается.
8. Деактивация учётной записи или замена пароля отзывает все её существующие
   серверные сессии. При последующем запросе со старой cookie доступ не
   предоставляется.
9. Сессия действует не более 30 дней с момента входа. По истечении срока
   сервер отклоняет её, даже если cookie всё ещё присутствует.
10. Перед созданием сессии повторно проверяются активность пользователя и
    неизменность проверенного пароля. Проверка и создание сессии выполняются
    при блокировке записи пользователя, чтобы изменение учётных данных не
    могло обойти отзыв сессий.
11. Production-приложение не запускается с пустым `SECRET_KEY_BASE` или с
    прежней публичной заглушкой из шаблона развёртывания.

## Следующий этап

Правила доступа сотрудника, руководителя и администратора к заявкам будут
описаны вместе с соответствующими контроллерами. Наличие роли само по себе не
предоставляет доступ без явной проверки авторизации.
