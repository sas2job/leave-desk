# Спецификация 005: управление сотрудниками

## Критерии приёмки

1. Только пользователь с ролью `administrator` может просматривать и изменять
   справочник сотрудников.
2. Администратор может создать сотрудника с именем, уникальным адресом
   электронной почты, паролем и ролью.
3. Адрес электронной почты нормализуется перед сохранением.
4. Администратор может изменить имя, адрес электронной почты, роль,
   непосредственного руководителя и активность сотрудника.
5. При редактировании пустое поле пароля сохраняет действующий пароль.
Новый пароль при создании или изменении содержит не менее 12 символов.
6. Непосредственным руководителем может быть только активный пользователь с
   ролью `manager`; сотрудника нельзя назначить руководителем самому себе.
7. Пользователя с непосредственными подчинёнными нельзя лишить роли
   руководителя или деактивировать, пока подчинённые не переназначены.
   Первое назначение подчинённого и изменение роли/активности руководителя
   сериализуются: при конкурирующих запросах сохраняется только допустимый
   результат.
8. Деактивация не удаляет заявки, решения и другие исторические данные.
9. В системе сохраняется хотя бы один активный администратор. Последнего
активного администратора нельзя деактивировать или лишить роли; одновременные
изменения двух последних администраторов сериализуются. Передача полномочий
разрешена после создания другого активного администратора.
10. Удаление сотрудников через интерфейс не поддерживается.
11. Пользователь без роли администратора получает `403 Forbidden`.
12. После успешной деактивации сотрудника или замены его пароля все его
    прежние сессии отзываются. Изменение других полей их не отзывает.
13. Некорректные значения роли, активности, даты рождения и идентификатора
    руководителя отклоняются при проверке модели.
14. Текстовые поля, переданные числом через JSON, отклоняются с HTTP 400 без
    создания или изменения сотрудника.
15. Логическое, дробное и недесятичное значение идентификатора руководителя
    отклоняется с HTTP 400 без изменения сотрудника. Пустое значение очищает
    необязательную связь с руководителем.
16. На новой БД оператор может создать первого активного администратора через
    интерактивную команду без передачи пароля в аргументах или переменных окружения.
    Повторный запуск не меняет существующую учётную запись. Если пользователи есть,
    а администратора нет, команда не создаёт новую запись автоматически.
17. Имя сотрудника содержит не более 100 символов, адрес электронной почты —
    не более 254 символов.
18. Дата рождения необязательна; можно сохранять любую конечную дату, в том числе
    до 2000 года. `infinity` и `-infinity` отклоняются моделью и ограничением БД.
    Если такая дата осталась в старой записи, форма редактирования открывается с
    пустым полем даты и позволяет администратору ввести корректную дату.
