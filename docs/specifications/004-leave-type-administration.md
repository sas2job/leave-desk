# Спецификация 004: управление видами отпусков

## Критерии приёмки

1. Только пользователь с ролью `administrator` может просматривать и изменять
   справочник видов отпусков.
2. Администратор может создать вид отпуска с уникальным кодом и названием.
3. Код нормализуется в верхний регистр.
4. Администратор может изменить название и доступность вида отпуска.
5. Администратор задаёт, входят ли федеральные нерабочие праздничные дни в
   продолжительность отсутствия.
6. Способ учёта праздников нельзя изменить после появления заявки этого вида,
   чтобы не пересчитывать исторические заявки задним числом. Первое сохранение
   заявки и изменение способа учёта сериализуются; при конкуренции изменение
   отклоняется либо заявка проверяется по уже изменённому способу учёта.
7. Отключённый вид не предлагается при создании новой заявки.
8. Отключение не удаляет существующие заявки и не изменяет их историю.
9. Удаление видов отпусков через интерфейс не поддерживается.
10. Пользователь без роли администратора получает `403 Forbidden`.
11. Повторный запуск seed-данных создаёт отсутствующие справочные виды, но
    сохраняет изменённые администратором название, доступность и способ учёта
    праздников существующего вида, в том числе после появления заявки.
12. Неизвестное значение способа учёта праздников отклоняется при проверке модели.
13. Некорректное значение доступности отклоняется с ошибкой `422` и не меняет
    данные вида отпуска.
14. Текстовые поля, переданные числом через JSON, отклоняются с HTTP 400 без
    создания или изменения вида отпуска.
